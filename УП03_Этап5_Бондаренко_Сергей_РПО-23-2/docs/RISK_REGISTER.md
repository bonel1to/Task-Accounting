# RISK_REGISTER.md

| ID | Риск | Причина | Вероятность | Влияние | Мера снижения |
|---|---|---|---|---|---|
| S-01 | Утечка `.env` или локальных секретов | Разработчик может случайно добавить файл окружения в Git | Средняя | Высокое | `.gitignore`, безопасные example-файлы, `scripts\security-check.bat`. |
| S-02 | Появление реального токена в коде | В проект могут добавить интеграцию с API и оставить ключ в JS | Средняя | Высокое | Хранить секреты вне frontend-кода, проверять `password/token/secret/api_key`. |
| S-03 | Нет серверной авторизации | Проект статический и не имеет backend-проверки ролей | Высокая | Среднее | Зафиксировать ограничение, при развитии добавить backend и проверку ролей. |
| S-04 | Данные доступны только в браузере пользователя | Используется `localStorage`, нет серверного хранилища | Высокая | Среднее | Предупреждать о demo-режиме, для production добавить БД и учетные записи. |
| S-05 | Потеря файлов проекта | Нет регулярного backup release/source-файлов | Средняя | Среднее | Использовать `scripts\backup.bat`, хранить release в GitHub и release-архиве. |
| S-06 | Backup не восстанавливается | Backup создается, но не проверяется | Средняя | Высокое | Запускать `scripts\restore.bat` после создания backup. |
| S-07 | Лишние открытые порты при локальной проверке | Разработчик может оставить локальный сервер/контейнер | Низкая | Среднее | Запускать `scripts\ports-check.bat`, закрывать ненужные процессы. |
| S-08 | Уязвимость будущей зависимости | Сейчас зависимостей нет, но они могут появиться | Средняя | Среднее | Добавить `npm audit`/`pip-audit` при появлении package manifest. |
