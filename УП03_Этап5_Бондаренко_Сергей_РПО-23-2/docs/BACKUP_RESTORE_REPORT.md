# BACKUP_RESTORE_REPORT.md

## Цель проверки

Проверить, что для проекта можно создать резервную копию важных файлов и подтвердить возможность восстановления.

## Особенность проекта

Task-Accounting является статическим frontend-приложением. Серверная база данных, backend API, uploads и контейнеры не используются. Пользовательское состояние хранится в браузере через `localStorage`, поэтому серверный backup БД неприменим.

## Что входит в backup

- `index.html`
- `styles.css`
- `script.js`
- `README.md`
- `.env.example`
- `.env.demo.example`
- `.env.production.example`

## Команды

```bat
scripts\backup.bat
scripts\restore.bat
```

## Результат

Backup создается в папке `backups\task-accounting_YYYYMMDD_HHMMSS`. Папка `backups/` добавлена в `.gitignore`, чтобы резервные копии не попадали в репозиторий.

Restore-проверка использует последний созданный backup и выполняет бинарное сравнение текущего `index.html` с копией из backup. Для статического проекта этого достаточно, чтобы доказать читаемость backup и возможность возврата файлов.

## Остаточный риск

Данные, созданные пользователем в браузере, остаются в `localStorage` конкретного браузера. Для промышленного использования нужен backend, база данных и регулярная серверная стратегия резервного копирования.
