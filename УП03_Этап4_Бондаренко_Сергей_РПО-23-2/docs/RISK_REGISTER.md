# RISK_REGISTER.md

| ID | Риск | Признак / доказательство | Вероятность | Влияние | Что сделать |
|----|------|--------------------------|-------------|---------|-------------|
| R-01 | GitHub Pages может быть недоступен после неверной настройки Pages | На этапе 3 первый deploy упал до включения Pages source | Средняя | Высокое | Проверять `Settings -> Pages -> Source: GitHub Actions` и фиксировать успешный workflow. |
| R-02 | Повторный deploy может быть запущен неправильной кнопкой | `Re-run jobs` создал два artifact `github-pages` | Средняя | Среднее | Использовать новый `Run workflow` или новый commit/push, не перезапускать старый job. |
| R-03 | Данные пользователя хранятся только локально | Проект использует `localStorage`, backend и БД отсутствуют | Высокая | Среднее | Описать ограничение в документации, при развитии добавить серверное хранилище. |
| R-04 | Браузер может запретить или очистить localStorage | Пользовательские данные зависят от настроек браузера | Средняя | Среднее | Проверять сброс демонстрационных данных и предупреждать о локальном хранении. |
| R-05 | Ошибка JavaScript может нарушить весь интерфейс | Проект работает одним `script.js` без сборщика и unit-тестов | Средняя | Высокое | Выполнять `node --check script.js`, smoke-тесты и проверку Console перед сдачей. |
| R-06 | Производительность может ухудшиться при росте данных | Все задачи рендерятся на клиенте из одного состояния | Низкая | Среднее | Контролировать Lighthouse/Performance и при росте проекта добавить пагинацию/фильтрацию. |
| R-07 | Отсутствие backend API ограничивает интеграции | Проверки API заменены HTTP-проверками статических файлов | Высокая | Низкое | Зафиксировать как архитектурное ограничение текущего учебного проекта. |
